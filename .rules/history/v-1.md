# 代码约束规则

## 1. 总则

- 可读性优先于聪明的写法。
- 显式优于隐式：能写清楚的地方不留猜测空间。
- 改动要小，一次只解决一个问题，提交信息说明做了什么。

## 2. 文件与目录

- R-001 · MUST · 新的**随包发布的源码**文件放在 `src/` 下并按模块目录归位（`src/sfc_core/src/<模块>/`、`src/sfc_core/include/sfc_core/<模块>/`）。开发期工具不适用本规则，放 `scripts/`：静态检查与批量改写脚本（`check_braces.js`、`static_check_e6.js`、`guard_diag_logs.js`、`patch_*.js`）、评测脚本（`evaluate_trajectory.py`、`run_and_eval_tum.sh`）。判定标准是"是否被 CMake 编译进产物"：进产物的进 `src/`，不进产物的一律进 `scripts/`。禁止把开发脚本放进 `src/` 混编，也禁止把运行时需要的代码放进 `scripts/`。
- R-002 · MUST · 测试文件放在 test/ 下，与源码目录结构保持一致。
- R-003 · SHOULD · 顶层目录保持 Thirdparty / config / picture / scripts / src 这几类，新增平行目录要说明理由。
- R-019 · MUST · 运行参数必须有单一来源（以 config/*.yaml 为准），头文件默认值与测试代码不得各自硬编码覆盖。
- R-022 · MUST · config/*.yaml 里的每个键必须对应结构体里的真实字段，且至少有一个 C++ 消费点；禁止保留「写了却没人读」的 dead key。新增字段时，同一改动内必须补齐 结构体字段 + loader 读取 + 消费者 三者，否则不要写进 yaml。反向同理：新增结构体字段若需要外部可配，必须补 yaml 键与 loader，不得只靠头文件默认值。
- R-023 · MUST · 每个配置结构体必须有且只有一个 yaml 归属文件，且只在 loadAllConfigs() 里合并一次。禁止两种写法：① loader 读取一个仓库里并不存在的 yaml（打 WARNING 后静默用默认值，等于该配置文件失效）；② 父配置与子配置各读一遍同一字段（两个合并点，取值不同时无法判断谁生效）。子配置（如 TrackingConfig::extractor_config / matcher_config）在父文件里只能写归属注释，不能写键。

## 3. 命名

- R-004 · MUST · 变量与函数使用 camelCase —— **仅适用于非 C++ 产物**（`scripts/*.js`、`scripts/*.py`、配置与测试脚本的变量/函数）。C++ 实现文件（`src/**/*.cpp`、`*.hpp`）沿用仓库既有的 ORB-SLAM3 风格：局部变量与函数参数用 snake_case（`baseline_samples`、`pose_before_loop`、`edge_added`），成员变量用 `m` 前缀 + PascalCase（`mCurrentFrame_`、`mAllMapPoints_`），成员函数用 PascalCase（`poseOptimization`、`retireBadMapPoints`）。新增 C++ 代码必须与所在文件的既有命名一致，不得在同一文件里混入两种风格。
- R-005 · MUST · 类型、类与组件使用 PascalCase。
- R-006 · MUST · 常量分两级命名，两者都必须带单位或语义后缀。①跨文件共享、需要外部理解的阈值：全大写加下划线，并在名字末尾标单位（`PNP_T_DIFF_THRESH_M`、`PNP_ROT_DIFF_THRESH_RAD`、`FRAME_JUMP_MAX_ROTATION_RAD`、`LOOP_MAX_KF_CORRECTION_M`）。②只在本翻译单元使用的 `constexpr`：`k` 前缀 + PascalCase + 单位（`kMapPointVoxelSize`、`kEMBaselineMinSamples`、`kGeoVerifyMinPx`），与仓库既有 ORB-SLAM3 风格一致。禁止无单位后缀的距离/角度常量（`constexpr double MAX_DIST = 8.0;` 无法判断米还是像素）。
- R-020 · MUST · 位姿与坐标变换用类型封装（Pose/SE3），显式区分世界系/相机系；反投影前必须校验 z 为正且坐标有限。
- R-026 · MUST · 跨模块传递的位姿必须在类型或变量名上标明参考方向（T_wc = camera→world，T_cw = world→camera），不得用裸 `Pose` 传递而不注明方向。OpenCV `solvePnP*` 与 g2o `VertexSE3Expmap`（含 `EdgeSE3ProjectXYZOnlyPose`、自写 `EdgeRobustReproject`）的位姿一律视为 T_cw；系统内部（`camToWorld`/`worldToCam`/`pts_3d_world`/`KeyFrameCacheEntry::world_pose`）一律为 T_wc。两者之间的转换只允许在单一出入口发生一次（如 `RobustPnPSolver::optimize` 出口），其余位置不得再做逆变换。

## 4. 单文件规模上限

- R-007 · MUST · 单个源文件不超过 400 行，超出就按职责拆分。
- R-008 · MUST · 单个函数不超过 60 行，嵌套不超过 4 层。

## 5. 注释与文档

- R-009 · SHOULD · 导出的函数写一段说明用途、参数与返回值的注释。
- R-010 · MAY · 复杂分支前写一行「为什么」，而不是复述代码做了什么。
- R-018 · MUST · 算法阈值等魔法数字必须提取为具名常量（含单位与来源注释），禁止在表达式内直接写字面量。

## 6. 错误处理与日志

- R-011 · MUST · 不吞掉异常，至少记录一次，并保留原始错误。
- R-012 · MUST · 对外返回的错误带可读的错误码与上下文。
- R-017 · MUST · 调试/诊断输出必须受开关控制（如 verbose_diag），禁止无条件的 std::cerr/std::cout 直接刷屏。
- R-021 · MUST · 诊断/调试输出必须受开关控制，但**错误与异常日志不得被该开关静音**——`FATAL`、`exception`、内参缺失、输入点数不足、求解失败等必须无条件输出，且不得因 `verbose_diag=false` 而消失；纯统计/过程量（迭代轮次、中间重投影均值、单点误差）才允许受开关控制。
- R-027 · MUST · 同一语义的度量（观测次数、被找到次数、内点数、有效深度数）在整个系统里只允许有一个事实来源。禁止在两个数据结构里各存一份同义计数器而不做同步：前端候选点结构（如 `MapPointCandidate`）与后端地图点结构（如 `mapping::MapPoint`）若都需要该度量，必须由同一个写入点同时更新两者，或让一方成为纯派生值（每次从另一方读取）。任何"只在 A 处 ++、B 处读"的写法必须被视为缺陷，即使 A、B 当前恰好取值相同。｜理由：`MapPointCandidate::observed_count` 只在 `checkReplacedInLastFrame()` 里 `++`，而该路径依赖的替换回调全仓零调用点，纯 VO 下计数永远停在创建时的 1；与之并存的 `mapping::MapPoint::found_count_` 则由 `addObservationToMapPoint()` 正常递增。`cleanOldMapPoints()` 读前者，于是每个关键帧创建完就把整张地图的点判为 `is_bad`，第 2 帧起 `poseOptimization` 拿不到对应点、直接返回 0。

## 7. 并发与死锁

- R-013 · MUST · 同时持有多把锁时按固定顺序获取，避免交叉等待。
- R-014 · SHOULD · 异步等待都带超时，避免无限挂起。

## 8. 自测与验证

- R-015 · MUST · 提交前运行项目的测试命令，并在提交信息里写明结果。
- R-016 · SHOULD · 新增行为先写一个会失败的测试，再让它通过。
- R-024 · MUST · SLAM 精度验收必须用 ATE/RPE（`scripts/evaluate_trajectory.py`），不得用"路径总长"或肉眼观察轨迹作为判据。路径总长对单帧位姿跳变极其敏感，同一份代码可能报出 478m 而真实约 5–12m，既不能判断位姿对错，也无法跨次运行比较。提交精度相关改动时，必须在提交信息里写明所用序列、对齐方式（是否 `--align`、是否估尺度）与 ATE rmse / RPE_trans rmse 数值。RGB-D 与双目不得开启对齐估尺度——尺度来自深度/基线，估尺度会把尺度错误藏进对齐变换里。
- R-025 · MUST · 任何进入图优化（PGO / BA）的约束，在接入前必须有证据证明它的平移量具备真实尺度——即该相对位移与地图点实测距离一致（误差 < 20%），并在日志里打印实测值。只给方向、不给尺度的量（Essential/单目 recoverPose 的 t、SVD 退化分支归一化的 t）不得直接作为 6-DoF 约束使用；拿不到可靠基线时必须拒绝该约束，不得用 1.0 m 之类的常数顶替。｜理由：B2 把只有方向的 Essential 平移固定成 1.0 m 接进 PGO，导致 43 次回环全是错误约束、fr1_desk2 路径总长从 478 m 膨胀到 1165 m。
- R-028 · MUST · 图优化中"哪些约束参与求解"必须由 `information()`、鲁棒核或显式拒绝来表达，**不得用 `setLevel()` 把整类约束移出优化**。调用 `initializeOptimization()` 时必须显式传入 level 参数并在同一处注释说明该 level 的语义；禁止依赖默认值。任何"某类边被批量设为 level>0"的写法必须附带一个断言或测试，证明剩余约束仍足以确定全部顶点（顶点数 - 固定顶点数 <= 参与优化的独立约束数）。
